# Helix v1.0 Plan — from “strong beta” to certifiable release

## 0. Definition of done (v1.0 gate)
A release is v1.0 only when all are true:
- `cargo fmt --check && cargo clippy --workspace -- -D warnings && cargo test --workspace` green on MSRV 1.75.
- `cargo build --workspace --release` succeeds.
- `helix --detect-only`, `helix --dry-run`, `helix --yes`, `helix --undo`, `helix --stop` all work on a clean machine.
- Detection reports non-null, accurate values on NVIDIA/AMD/Intel.
- Rollback restores every applied Class B/C tweak.
- No “play” naming remains except legacy-compat reads.
- CI compile/test job green; documented manual hardware smoke path exists.
- README/install/docs match actual behavior and paths.

## Phase 1 — Correctness blockers (P0, do first)
Goal: remove “looks broken” failures.

1. Clippy green (pre-existing `pe.rs`)
   - Files: `crates/helix-core/src/binary/pe.rs`
   - Change `&mut Vec<u8>` params to `&mut [u8]`, add `# Errors` docs or scoped allows.
   - Gate: `cargo clippy --workspace -- -D warnings`.

2. Error propagation end-to-end
   - Files: `orchestrator.rs` (`final_error`), `main.rs` (`display_error_with_context`)
   - Store/return original `PlayError`; remove generic `OrchestratorFailed` replacement.
   - Gate: failing run prints original error type and message.

3. Prefix verification layout
   - Files: `crates/helix-core/src/execution/prefix.rs`
   - Detect prefix by `system.reg` (pfx first, then base); verify correctly.
   - Add WineGE integration test.
   - Gate: `cargo test -p helix-core execution::prefix`.

4. Rollback manifest completeness audit
   - Files: `orchestrator.rs` (`record_rollback_entries`)
   - Verify arms for `SplitLockMitigate`, `UlimitNofile`, `NvidiaPersistenceMode`, `NvidiaClockLock`.
   - Gate: rollback test restores all applied values.

5. Persistent tweak state
   - Files: `execution/system.rs`, new state file under data dir
   - Persist Class B applied values; skip re-apply/re-prompt when already at target.
   - Gate: second launch does not re-prompt for Class B tweaks.

## Phase 2 — Zero-config detection (P0/P1)
Goal: make `--detect-only` trustworthy.

6. NVIDIA VBIOS max clock
   - Query `nvidia-smi` clock data; populate `nvidia_vbios_max_clock_mhz`.
   - Gate: on NVIDIA hardware, non-null MHz and clock-lock tweak appears in plan.

7. Vulkan version + DX12 feature level
   - Parse `vulkaninfo --summary`; set feature level for VKD3D-Proton.
   - Gate: plan sets `VKD3D_FEATURE_LEVEL` when VKD3D-Proton selected.

8. Laptop GPU inference
   - Infer from model name / chassis; cross-check laptop CPU.
   - Gate: RTX 3050 Laptop reports `is_laptop_gpu: true`.

9. Shallow tool detection
   - `gamemode_installed` checks daemon; `dxvk_installed` checks libs/config; record versions.
   - Gate: `--detect-only` reflects installed state accurately.

## Phase 3 — Product UX (P1)
Goal: make it usable and polished.

10. Steam launch integration
    - Accept `%command%`, detect Steam app id from env/args, set `steam_app_id`.
    - Gate: `helix %command%` works as Steam launch option.

11. Clean stop command
    - Terminate tracked PID, run post-exit hooks, restore guards.
    - Gate: process exits cleanly.

12. Cache/checkpoint dir names
    - `{sanitized_name}-{hash[:8]}`.
    - Gate: directories human-identifiable.

13. First-run shader-compile UX
    - Detect missing DXVK cache; print estimated wait/progress hint.
    - Gate: first run shows guidance.

14. GUI progress (optional)
    - `zenity`/`kdialog` dialog with spinner fallback.
    - Gate: manual smoke test on large download.

## Phase 4 — Quality, tests, CI (P1/P2)
Goal: make CI meaningful and catch regressions.

15. PE fixtures validity
    - Align generated PE layout with in-memory builder or remove invalid fixtures.
    - Gate: `analyze_binary` succeeds on every fixture.

16. End-to-end happy-path test
    - Mock runner/prefix/system; drive orchestrator to `Validated`.
    - Gate: new integration test in `cargo test --workspace`.

17. CI real-hardware/manual coverage
    - Keep container compile/test job; add documented manual workflow for `--detect-only` on GPU runner.
    - Gate: workflow green on both paths.

18. Docs accuracy pass
    - README, install.sh URLs, CONTRIBUTING, CLAUDE/current plan.
    - Gate: new contributor can build/test from docs.

## Phase 5 — Release engineering (P2)
19. Versioning/changelog
   - Tag v1.0.0, release notes, migration notes.
20. Packaging/install
   - Verify `install.sh`, polkit policy, binary install paths.
21. Security review
   - Audit helper whitelist, polkit, rollback.
22. Soak/manual matrix
   - Test on Ubuntu/Fedora/Arch with NVIDIA/AMD/Intel where available.

## Execution order
1. Phase 1 (correctness) — unblocks everything.
2. Phase 2 (detection) — fulfills zero-config promise.
3. Phase 3 (UX) — product usability.
4. Phase 4 (quality/CI) — confidence.
5. Phase 5 (release) — ship.
